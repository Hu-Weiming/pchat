# Windows 0.1.1 操作验收

本机目标安装目录：`D:/Dev/apps/Pchat`，入口 `pchat-desktop.exe`。具体已完成项以 [开发进度](./DEVELOPMENT-PROGRESS.md) 为准，本文是操作清单。生产版不需要开发服务器。关闭窗口收进托盘；托盘“退出 Pchat”停止后台。

## 当前连接

本机已启用用户提供的 DeepSeek、千帆加密凭证以及13个人物的应用工作流绑定。无需重新输入Key或走旧的独立知识库采集步骤。密钥由Rust Host通过当前Windows用户的DPAPI解密，仅用于供应商认证；不进入Node、Harness或SQLite。

维特根斯坦绑定存在远端兼容值：应用主分支将group与“维特根斯坦”比较，因此本机工作流group发送该值，界面仍按“分析哲学与语言转向”分类。远端改正条件后须同步调整本机绑定。

## 主流程

1. 新建讨论，保留“按问题自动选择”或显式选择1–3个人物，选择知识模式。
2. 提问后，DeepSeek整理问题并选人；程序校验目录与显式选择，逐人物串行查阅千帆原典；全部返回后仅发起一次最终DeepSeek请求。
3. 各人物回答以未完成草稿逐步出现。最终结果校验通过后，显示分别回答、对用户明确观点的简短回应和本轮总结。纯提问不强行生成观点点评。
4. 回答中的[1]等编号对应该人物“查看依据”里的片段。“已引用”与“未引用”区分最终回答选用情况。没有完整版本、译者和稳定定位时不提供冒充原典的直接引文。

## 操作验收清单

- 回答A期间提交B、C：保持FIFO，后续问题不进入A的上下文；可撤回未执行问题。
- 停止：未完成输出停止，已处理草稿保留，后续队列暂停，迟到结果不覆盖状态。
- 退出并重开：历史和草稿保留。未确定是否成功的付费调用进入“等待你的决定”，不得自动重试；明确继续只重新调用未完成步骤，复用已保存检索结果，保留旧尝试和草稿。
- 至少两份有效回答时可展开原回答对照。总结必须保留推演/资料不足边界，不能把“未检索到支持”说成“作者明确反对”。
- 安装升级保留数据库，迁移前产生一致性备份；新协议无法握手时拒绝写入。

## 内容验收边界

接口连通、dataset匹配和结构校验均不代替哲学内容审查。当前知识库片段存在译者序、出版社说明、编者脚注和疑似误收录；程序做保守排除并保留连续原文及哈希，仍需逐例检查人物立场、思想阶段、语境和引用是否支持相应句子。全时期文集也不能自动证明某个具体思想阶段。不得仅凭安装成功宣布总MVP验收完成。

## 数据和诊断

状态默认位于 `D:/Dev/state/pchat`。累计预算100为内部调用单位，不是人民币；模型调用计1、工作流检索计2，重启不重置。实际费用以供应商账单为准。

加载 `D:/Dev/pchat-env.ps1` 后，运行 `scripts/verify-installed.ps1 -Executable D:/Dev/apps/Pchat/pchat-desktop.exe -OutputRoot D:/Dev/temp/pchat` 检查真实安装页查询、订阅和退出清理，不发供应商请求。

`scripts/verify-workflow-live.mjs --run` 为显式付费验证，使用隔离的D盘状态目录；`--retrieval-only --roles=`逐一验证全部人物，`--diagnostic`使用仅存在于Rust测试程序的官方异步节点诊断接口。私有原文结果保留在D盘，不提交仓库。
