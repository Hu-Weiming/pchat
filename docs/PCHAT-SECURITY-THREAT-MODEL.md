# Pchat Security Threat Model

状态：2026-09-08 已确认。本文覆盖 Windows MVP，不把本机管理员、公开互联网服务或未来插件市场假装成已经解决的问题。

| 威胁 | 必须处理 | 主要控制 | 验证方式 |
| --- | --- | --- | --- |
| 恶意网页调用本地 Runtime | 是 | MVP 不开放 localhost 或系统浏览器入口 | 端口扫描与安装冒烟测试 |
| UI 脚本漏洞调用高权限能力 | 是 | Tauri 最小权限；只暴露结构化命令和通道 | 权限清单审查与负面测试 |
| Runtime 借安全网络能力访问任意网址 | 是 | connectionId、供应商端点允许清单、Host 注入凭证 | 非允许端点必须被拒绝 |
| API Key 进入数据库、日志或 UI | 是 | 用户手动录入；CredentialVault；统一脱敏 | 搜索构建产物、数据库、日志和测试快照 |
| 安装包或朋友测试泄露负责人主 Key | 是 | 永不内置 Key；只提供低风险测试专用 Key | 发布检查与密钥轮换演练 |
| RAG 内容或 prompt injection 修改系统规则 | 是 | 资料按不可信内容隔离；知识模式不可由模型改变；MVP 无工具执行 | 对抗资料测试与输出评测 |
| 人物读取其他人物资料 | 是 | 每个 RoleRun 冻结独立 corpus scope | 串库测试 |
| 崩溃恢复自动重复付费 | 是 | 调用尝试记录、`OUTCOME_UNKNOWN`、用户确认后新建尝试 | 在发送前后模拟崩溃 |
| 重复启动造成多 Runtime 写库 | 是 | single-instance 与唯一 Runtime owner | 重复启动和孤儿进程测试 |
| 数据库升级或断电造成损坏 | 是 | WAL、事务、迁移前一致性备份、失败即停 | 故障注入和恢复演练 |
| 流式事件丢失导致界面状态错误 | 是 | 持久投影为权威；snapshot + lastEventSeq | 断线重连测试 |
| 费用或并发失控 | 是 | 全局并发、速率和费用上限 | 压力与限额测试 |
| 本机管理员提取自己填写的 Key | 无法彻底防止 | CredentialVault 只减少误操作和普通泄露 | 在产品说明中如实声明 |

## 安全设计原则

- 默认不给能力；按实际功能添加最小权限。
- 模型输出、RAG 内容和 UI 输入都不是可信指令。
- 凭证只在最靠近供应商请求的位置使用，不向普通模块传播。
- 安全失败时停止相关操作并保留可诊断信息，不静默降级到更宽权限。
- 参考 Codex、Claude Code 等成熟产品时，只采用官方公开且适合 Pchat 的做法，不假定其未公开实现。
