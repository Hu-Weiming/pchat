# 人物资料说明选路第一版

日期：2026-10-12。用户已确认由 AI 生成并直接启用说明；允许无匹配提前返回；自动选人默认一位，需要对照时最多三位。每个独立功能通过检查后提交、创建 PR 并合并到 main，作者使用 Hu-Weiming，新增关键逻辑使用中文注释。

## 已确认流程

用户原问题与人物资料说明 → DeepSeek 选路 → 分叉：

- 匹配：冻结人物与资料版本，千帆分别检索原文，再由 DeepSeek 依据原文回答及总结。
- 无匹配：首个 DeepSeek 请求同时返回简短说明和可继续细分的提问；保存并显示后直接结束本轮，不执行 RAG 或第二次模型调用，不暂停后续 FIFO 问题。

说明仅用于选路，不能充当回答证据。保留用户原句，附加中性检索表达；不能把“无聊、不想玩手机”直接认定为虚无主义或疾病。用户明确选人时不得换人；无匹配只表示本次未找到合适资料方向，不宣称整库一定没有相关内容。

## 自动说明

每个人物／思想阶段保存简短说明及其资料版本。使用实际取得的原文生成，目标约 100–200 字，不凭思想家百科知识填写。

当前千帆工作流只能返回检索片段，无法列举全库目录。第一版自动说明必须明确是基于抽样原文的导航线索，不能宣称完整覆盖；不需要人工确认，但用户可重生成或修改。空检索、未知结果或生成校验失败时保持原说明，不自动重复付费。

完整目录、心理学证据类型、无限规模检索及全库内容验收不属于本切片。目录容量提高至 100 只表示输入容量；不承诺选路准确率或恒定成本。

## 功能与检查

1. 人物说明选路和无匹配分叉：共享契约、冻结快照、模型选路提示、Harness 持久结算与页面显示。
2. 自动说明准备：已有角色配置入口、受限原文抽样、一次模型说明生成和原子保存；保留已有 workflow 绑定。

使用已确认的公共检查面：contracts schema、PchatHarness 的 dispatch/query/events、Model/RAG ports、配置处理入口和 SQLite 重开。必须验证无匹配没有额外外部调用、FIFO 继续、显式人物不替换、旧快照可读和未知付费请求不自动重试。真实付费内容质量另行验收，不以离线测试代替。

本机缺 Windows SDK／MSVC 链接工具时，继续完成 TypeScript、前端及 Runtime 检查；新原生安装包构建须如实记录限制，不修改 C 盘工具目录。

## 第一版操作

在「连接与资料设置 → 人物资料说明」选择已有角色，点击「自动生成并启用说明」。无需重新上传或替换千帆工作流。一次逻辑检索加一次 DeepSeek 说明生成；当前 workflow 检索包含两个 HTTP 请求。失败保留原说明，不自动重试；结果未知可能已产生费用，后续重新点击是新的明确请求。

说明带固定抽样标记，实际使用的原文、来源版本及生成状态保存在应用状态目录的 `description-jobs`。成功更新角色说明版本；之后提交的问题使用新说明，已经排队或执行中的问题保持旧快照。入口沿用既有资料配置权限，成功后按既有机制重启 Runtime；生成期间禁止其他设置操作。准备说明是按需的资料准备调用，不能把它的固定调用次数当作人民币费用保证。
