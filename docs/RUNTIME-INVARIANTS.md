# Pchat Runtime Invariants

状态：2026-09-18 已确认。本文只记录实现不得破坏的规则；具体类名、数据库表名和算法可以调整。

## 会话、轮次与队列

- **INV-001**：一个 Conversation 同时最多有一个 active Turn。
- **INV-002**：同一 Conversation 的 Question 严格 FIFO；待处理问题不得进入当前 Turn 的上下文。
- **INV-003**：不同 Conversation 可以并行，但必须受全局 Turn、RoleRun、外部调用和费用上限控制。
- **INV-004**：一个 Question 只创建一个 Turn；每位参与人物各创建一个 RoleRun。
- **INV-005**：`StopTurn` 作用于该 Turn 下所有未完成的 RoleRun；停止后的迟到结果不得覆盖最终状态。
- **INV-006**：Question、Turn、RoleRun 和外部调用尝试均使用正式状态机；非法状态转换必须被拒绝。

## 上下文、人物与证据

- **INV-007**：Turn 开始后，其人物、知识模式、模型、资料范围和版本快照不受后续消息或设置修改影响。
- **INV-008**：RoleRun 只能使用自己冻结的 corpus scope；其他人物的发言不能替代自己的资料依据。
- **INV-009**：Comparison 只能整理本轮至少两个有效 RoleRun 已表达的内容，不得产生新的哲学论断。
- **INV-010**：KnowledgeMode 只能由用户显式选择或通过明确命令改变，模型不得自行扩大权限。
- **INV-011**：EvidenceSnapshot 保存当时实际使用的文本、来源定位、内容校验值和相关版本；知识库更新不得静默替换历史依据。
- **INV-012**：思想日记及评论永远不进入人物上下文、摘要或知识库。

## 恢复、事件与外部费用

- **INV-013**：commandId 只保证 Pchat 内部命令幂等，不承诺外部供应商 exactly-once。
- **INV-014**：可能已被供应商接收但结果未知的外部调用进入 `OUTCOME_UNKNOWN`，恢复流程不得自动重试。
- **INV-015**：用户明确重新生成时必须创建新 attemptId，并保留与原尝试的关联。
- **INV-016**：SQLite 持久状态是唯一权威；实时事件只通知变化，不能成为 UI 唯一事实来源。
- **INV-017**：每个查询投影返回 `lastEventSeq`；事件订阅必须从该快照书签之后开始。

## 平台、凭证与数据

- **INV-018**：`packages/harness` 不依赖 Node、Tauri、React、具体数据库或供应商 SDK，只依赖 ECMAScript、contracts 与注入的 ports。
- **INV-019**：Windows 同时只能有一个 Pchat 实例、一个 Runtime 所有者和一个数据库写入架构。
- **INV-020**：数据库结构迁移前必须创建一致性备份；迁移或版本握手失败时不得继续写入。
- **INV-021**：软件与安装包不得内置 API Key；凭证值不得进入 SQLite、日志、UI 或普通 Harness 协议。
- **INV-022**：模型和 RAG 只能通过统一 port 及具体 adapter 接入；Host 网络能力必须限制到已登记的供应商端点。
- **INV-023**：人物资料包只能是经过校验的数据，不得执行代码或注册命令。

## 检索与生成分工

- **INV-024**：检索前的模型选路只可从已登记人物/思想阶段中提出建议；Pchat 校验并在 Turn 开始前冻结范围，用户明确选择的人物不得被模型替换。首版 RAG 只检索已确认的哲学家原典，返回原始文本片段和中性来源元数据，不生成立场或候选回答；最终解释由 ModelPort 在证据约束下完成。
- **INV-025**：可核实为人物本人发言的访谈可作为该人物原典依据；引用访谈的回答及依据展示必须标明访谈来源，采访者和编者发言不得伪装为该人物立场。来源形式或发言归属未核实时不得将其标为已确认访谈。

## 验证要求

每条不变量至少由自动化测试、安装/升级测试或安全检查中的一种验证。实现评审若发现代码与本文冲突，以本文为准；如确需改变，必须先更新产品共识和本文，再修改实现。
