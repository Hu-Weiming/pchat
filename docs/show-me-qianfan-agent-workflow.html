02 / CANVAS

工作流画布顺序

这一条流程使用千帆现有的开始、代码、分支器、知识库、参数聚合、大模型与结束节点。每个人物阶段复制一条固定知识库分支，最后汇合。

01

开始

接收当前问题，以及 Pchat 冻结的类别、人物、阶段、知识模式和资料版本。

02

校验＋分支

只允许已登记的组合。分支器把请求送进对应人物阶段的知识库；否则直接拒绝。

03

知识库检索

每条分支只绑定该人物的库。原典模式用原典范围或文档标签硬过滤。

04

参数聚合

将各固定分支输出合并成同名字段，交给一个下游处理流程。

05

代码选段

按片段 ID 去重、限制每本书与总段数；保留选中片段的完整原文和原始 ID。

06

证据不足分支

无有效证据时返回 INSUFFICIENT，不启动生成节点。

07

大模型回答

仅用筛选后的片段回答，每条依据引用 [E1] 等编号；不能自行生成来源 ID。

08

校验＋结束

引用编号必须属于本次证据。结束节点直接返回回答、证据 JSON、状态与资料版本。

压缩发生在哪里？

发生在检索结果：初取 8 段，保留约 4–6 段，每本书至多 2 段。丢弃整段低相关内容，不改写证据原文。数值是第一轮调试起点。

两个模型怎样分工？

千帆生成带证据的候选回答；Pchat 核验后，把回答和证据交给 DeepSeek 形成最终人物表述。两次生成分别记录，也分别计费。

05 / RELEASE GATE

调试通过再发布

同人物有证据

问该人物自己的书，返回回答与原始片段 ID；两者的编号对应。

跨人物不串库

拿另一位人物的专属问题试问，结果不能偷用对方知识库。

空证据明确拒绝

没有命中的问题返回 INSUFFICIENT，不编造出处。

知识模式隔离

原典模式不能召回研究资料；开放拟构必须有明确选择。

版本更新可追溯

新版本不能静默替换历史片段；旧回答保留当时证据。

发布版真实响应

记录 Agent 应用 ID、版本和一份脱敏响应，再把解析器接入 Pchat。
