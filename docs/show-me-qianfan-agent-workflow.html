01 / DATA FLOW

一轮请求怎样走

每一步都在 Pchat Runtime 编排。千帆不会接收 DeepSeek 密钥，也不会直接替 DeepSeek 回复用户。

01 · 用户提交问题进入会话内 FIFO 队列；显式选人和知识模式随问题保存。
02 · DEEPSEEK识别范围提出人物／阶段或流派，并给每位人物一条中性检索问题。
03 · PCHAT冻结路由核对已登记人物、数量、用户选择、知识模式与资料版本。
04 · 千帆 API检索原文每位人物独立查指定库；返回片段和来源 ID。
05 · DEEPSEEK最终回答依据编号原文解释并引用；Pchat 校验、保存后显示。
流派问题：先把流派映射到已登记的具体人物，最多选择一至三位；不能把整个流派当作一个混合知识库。用户已选人物时，DeepSeek 不能换人。
02 / OWNERSHIP

三方各自负责什么

DeepSeek 第一次：只做选路

返回人物 ID、阶段 ID、可选流派 ID 和检索词。它不能决定知识库 ID、扩大知识模式，或在没有证据时预先编写人物立场。

百度千帆：只给原文

依据 Pchat 给定的库 ID、文档范围和检索词返回原始片段。片段附中性来源元数据；不生成摘要、候选答案或“某人认为”的立场句。

Pchat：信任边界

校验路由与资料归属，按人物拆开检索，把真实片段、版本和内容哈希保存为证据快照。结果未知的付费调用不自动重试。

DeepSeek 第二次：面向用户

拿到原始证据和人物规则后总结、比较、回复。原典、解释、推演分清；每条实质论断引用本轮有效证据。

03 / CONFIGURATION

需要固定的参数

模型只提议人物和检索词。真正的知识库与文档范围全部来自 Pchat 已确认的配置表，不接受模型直接指定。

参数来源校验与用途
question / knowledgeMode当前用户问题与显式设置只取本轮问题；模型不能把模式升级为开放拟构。
roleId / stageIdDeepSeek 建议，或用户明确选择必须在已登记目录；用户显式选择优先；一至三位。
schoolIdDeepSeek 建议或用户问题只作为选人线索；映射到具体人物后才能检索。
searchQueryDeepSeek 选路输出每人物独立检索词；校验长度与内容；不通过时停下或用当前问题。
knowledgebaseIdPchat 人物／阶段配置表每次检索只用一位人物的已确认库，禁止跨人物混查。
documentIds / corpusRevisionPchat 原典清单三个知识模式都只查原典文档，冻结版本；历史回答保存当时证据。
raw evidence千帆检索响应保留原文、知识库／文档／片段 ID 和哈希，不改写成解释句。
建议初值：混合检索召回 8 段、重排后至多 6 段、每本书至多 2 段。上线前需用真实资料做召回评测；这些数字不是产品规则。

05 / ACCEPTANCE

发布前这样验

尊重显式选人用户点选康德时，选路模型不能改成其他人物。
流派不串库流派先转具体人物，每位人物只查自己的原典范围。
千帆没有立场输出返回值只含原始片段与中性来源，不含候选回答。
证据不足不编造零片段或校验失败时返回资料不足，不强行生成引文。
引用可回查每个 [E1] 都能对应本轮真实片段、文档和版本。
队列与付费安全选路不读取后续问题；未知调用不自动重复付费。
当前是修订后的设计方案。现有代码已具备逐人物“千帆检索 → DeepSeek 生成”；第一次 DeepSeek 选路与所有模式只检索原典的收紧规则仍需实现和测试。真实密钥和资料未接入，在线内容质量尚未验收。
