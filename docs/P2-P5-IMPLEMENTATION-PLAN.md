## P2：让同一领域状态成为持久事实

- SQLite adapter 实现现有 `RuntimeStore.read/transaction/subscribe`。领域状态、命令回执和 journal 同事务提交；通知必须在 COMMIT 后且 transaction Promise 回执前同步发送，停止和新运行者接管立即撤销旧执行权限。
- 保存会话、原始问题、轮次、人物执行、尝试、费用预留、实际依据、草稿与事件。业务状态为权威，不依靠重放所有事件重建状态。
- 外部调用不能发生在 SQL 事务内。`PREPARED` 和 `IN_FLIGHT` 分别落盘；结果落盘失败时不自动重新调用。新运行者把未确定调用转为 `OUTCOME_UNKNOWN`，等待用户决定。
- 明确 Store 开关生命周期、单一 Runtime 所有权、WAL、FULL 同步、foreign keys、busy timeout、schema version 与迁移记录。未知较新 schema、备份失败或迁移失败均停止打开。
- 先以独立数据库执行现有 Store/Harness 验收，再做真正的进程中断与重开。软件进程强制结束测试不声称等价于物理断电测试。

## P3：在接 UI 前确定真实工作流

- `PchatClient` 维持 dispatch/query/events；Transport 使用明确协议版本和 requestId 关联传输。请求重发沿用 commandId；未知回执不能被 UI 变成第二个业务命令。
- Connection 保存供应商类型、模型、知识库绑定与配置修订，不保存凭证。人物包与 Corpus scope 独立，模型选择不写入人物资料包。目录显示草稿/人工确认状态。
- 上下文按执行配置预算保留系统规则、当前问题、人物和依据，再容纳最近完整历史及可审计检查点。原始问题和回答永久保留；压缩失败缩短历史，不编造用户观点。
- 将单人物执行推广到同一 Turn 下的 2–3 个 RoleRun；不复制一套多人物队列。每个人物有独立 scope、尝试与草稿；新人物可读以往讨论，但不能把别人的发言作为原典依据。
- 对照只整理本轮已有有效回答，提供可追溯到回答的结论、前提、概念与分歧；不借对照新增哲学论断。不足两份有效回答时显示原因。
- 新会话默认推演；开放拟构由用户显式选择。模式分支保留来源关系与旧回答的原有标记，历史不能被重新贴标签。

## P4：可操作的产品界面

采用已确认 Atelier 原型的布局、色彩和阅读层次。实现会话侧栏、人物选择、知识模式、长文回答、队列、停止、恢复与明确重新生成、依据详情和连接设置。交互直接表达用户能做什么，不把内部模块名放进产品流程。

正式 UI 不导入 SQLite、Harness 执行器或供应商代码。窗口重建时先读取投影和书签，再订阅变化。凭证输入属于专门的 Host 设置通道：仅写入一次，保存后清空，不通过普通 Harness 命令或查询回读。

没有密钥和已绑定资料时，界面清楚引导配置。测试替身只用于测试和明确标识的独立验收环境，不把预制哲学答案当成真实生成结果。

## P5：供应商适配与交付

- DeepSeek 与千帆分别实现 ModelPort/RAGPort；未来开发机检索只需增加 RAG adapter，本次不实现本地模型和本地知识库。
- 千帆采用用户在控制台上传和管理的独立知识库，Pchat 调用独立检索接口，不接应用聊天接口或自动上传服务。按人物 scope/文档筛选限制请求，保存实际片段、来源与校验值。
- 按 2026-09-18 确认的[双阶段工作流](./QIANFAN-AGENT-WORKFLOW-PLAN.md)，新增第一次 DeepSeek 选路：从已登记人物/思想阶段或流派中提出受限目标，Pchat 校验并在检索前冻结；千帆只返回已确认哲学家原典的原始片段和中性来源，第二次 DeepSeek 调用负责最终回答。现有检索→生成链路保留，选路状态与原典范围收紧须另做测试驱动实现。
- 远端知识库可能原地变更，不能靠增加本地 revision 假装冻结远端。接入采用可核验的资料清单/版本约束，无法确认时拒绝当作旧版本执行；历史始终显示原依据快照。
- Rust Host 校验供应商和固定端点、注入凭证、处理超时及取消，不接受任意 URL。私有通道只传 connectionId 与结构化请求，响应和日志统一限制大小及脱敏。
- DeepSeek 流适配覆盖分片、保活、空输出、结构化结果校验、finish reason、断流与未知结果；不展示 reasoning_content 或原始供应商 JSON。
- 替换 P0 的假凭证、统一短超时和强杀退出策略。显式退出先保存状态并暂停，再在有界期限后清理；隐藏窗口不退出。
- 构建 Windows 本机验收包，验证启动、单实例、托盘、退出、重启历史、迁移失败和 UI 可操作性。所有开发产物与日志使用 D 盘开发目录。

## 验收证据与未具备条件

每阶段先写一个公共 interface 的失败场景，再实现和验证；主门禁包括类型检查、业务测试、依赖隔离、可移植运行和对应 adapter 集成测试。Git 提交与推送遵循根目录 AGENTS.md。

代码可在无真实密钥与资料时完成，但以下结果必须等用户提供条件后实测：DeepSeek/千帆账户权限、余额与模型可用性、实际取消计费、真实召回、译本定位、远端版本隔离及哲学论断支持度。最终交付报告明确区分工程通过、用户可操作验收和仍待真实内容验证，不能宣称产品已通过尚未执行的在线或内容测试。
